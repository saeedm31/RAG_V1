## 💡 Why it exists

Contracts, research papers, internal reports — many documents are too sensitive to paste into a cloud chatbot.
RAG_V1 gives you the same "chat with your documents" experience, but fully offline:

- **Private by design** — the embedding model and the LLM both run locally. No API keys, and after the one-time model download, no cloud calls.
- **Answers from your files** — the model only answers from the passages it finds in your PDFs, and says so when the answer isn't there.
- **Shows its sources** — every answer comes with the text passages it was based on.
- **Simple to run** — one Streamlit app, a few Python packages, one local model.

## ✨ Features

- 📤 Upload one or many PDFs from the sidebar
- 🔍 Semantic search with `all-MiniLM-L6-v2` sentence embeddings
- 💬 Chat interface with conversation history
- 📖 "View sources" panel for every answer
- 🤖 Answers generated by **Llama 3.2** through Ollama (swap in any Ollama model)
- 🧩 Works with PyMuPDF, pdfplumber or pypdf — whichever is installed
- 🐳 Dockerfile and `docker-compose.yml` included

## 🧠 How it works

```
 PDFs ──► extract text ──► split into chunks ──► embed (MiniLM)
                          (500 words, 50 overlap)        │
                                                         ▼
 Question ──► embed ──► cosine similarity ──► top 3 chunks
                                                         │
                                                         ▼
                                  Llama 3.2 (Ollama, local) ──► answer + sources
```

1. **Ingest** — text is pulled from each PDF and split into overlapping 500-word chunks.
2. **Embed** — each chunk is turned into a vector with a small local sentence-transformer model.
3. **Retrieve** — your question is embedded the same way, and the 3 most similar chunks are picked by cosine similarity.
4. **Answer** — those chunks are sent to a local Llama 3.2 model with an instruction to answer only from that context.

Embeddings are kept in memory for the session, so there is no database to set up. Click **Process PDFs** again after adding new files.

## 🚀 Quick start

**1. Install Ollama and pull the model**

```bash
curl -fsSL https://ollama.com/install.sh | sh
ollama pull llama3.2
```

**2. Run the app**

```bash
git clone https://github.com/saeedm31/RAG_V1.git
cd RAG_V1
pip install -r requirements.txt
streamlit run app.py          # opens http://localhost:8501
```

**3. Use it**

1. Upload PDFs in the sidebar (a sample paper is already in `pdf_inputs/`)
2. Click **🔄 Process PDFs**
3. Ask a question in the chat box
4. Open **📖 View Sources** to see which passages were used

### Run with Docker

```bash
docker-compose up --build     # or ./run_docker.sh
```

The container talks to Ollama running on your own machine (`OLLAMA_HOST` is already set in
`docker-compose.yml`), so start Ollama on the host first. On Mac and Windows (Docker Desktop) plain `ollama serve` works;
on Linux, let containers reach it with `OLLAMA_HOST=0.0.0.0 ollama serve`.

### Use a different model

Change `model='llama3.2'` in `app.py` to any model you have pulled with `ollama pull`.

## 🛠️ Troubleshooting

| Problem | Fix |
|---|---|
| "Model not found" | `ollama pull llama3.2` |
| "Error generating response" | Make sure Ollama is running: `ollama serve` |
| Port 8501 in use | Change the port in `docker-compose.yml`, or stop the other app |
| Very large PDFs are slow | Works best with files under ~50 MB |
